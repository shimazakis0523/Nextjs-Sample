# 仕様品質チェックリスト: Todo編集

**目的**: 設計(`/speckit-plan`)に進む前に、仕様の完全性と品質を検証する
**作成日**: 2026-09-01
**対象**: [ユースケース記述(Todo編集)](../../../../../doc/フロントエンド設計書/業務1_Todoダッシュボード/ユースケース記述_Todo編集.md)・[画面定義書(Todo編集)](../../../../../doc/フロントエンド設計書/業務1_Todoダッシュボード/画面定義書_Todo編集.md)

## 内容の品質

- [x] 実装詳細(言語・フレームワーク・API仕様等)が含まれていない — `PUT /api/todos/{id}`は
  Principle VIが許可するエンドポイント参照(メソッド+パスのみ)に留まる
- [x] タイトルが業務行為の名前になっている(「〜画面」という画面名になっていない) —
  「Todo編集」
- [x] ユーザーストーリー形式(優先度・独立テスト可否等)を使っていない

## ユースケース記述の品質

- [x] [要確認]マーカーが残っていない
- [x] 各ユースケースに基本フロー・代替/例外フローが定義されている
- [x] スコープの境界が明確である(モーダル形式を明記。遷移元(起動方法)はPrinciple VIに
  より記述していない)

## 画面定義の品質

- [x] 画面入出力仕様に、画面上の全要素(入力・出力・ボタン)が列挙されている
- [x] 入出力区分と種別が別の列になっている
- [x] 項目単位の見た目・制約が、各項目の行の中に記載されている
- [x] 処理仕様の1行目が初期表示になっている
- [x] 処理仕様がフロントエンドの範囲に閉じている(API/DBの内部仕様に踏み込んでいない)

## 備考

- 未完了の項目がある場合は、`/speckit-clarify`または`/speckit-plan`に進む前に
  ユースケース記述・画面定義書を修正すること
- Todo一覧側にも編集ボタンの導線を追加した(画面定義書_Todo一覧.md・
  ユースケース記述_Todo一覧.mdを同時に更新)。処理仕様の変更に伴い、
  `update-screen-flow-diagram`・`update-e2e-test-spec`を実行済み。一覧への更新反映の
  詳細(callback配線)は既存のTodo新規登録と同様、画面定義書ではなく詳細設計書の
  コンポーネント関係で記述する。
