# 画面仕様書: Todo一覧画面

**画面ID**: `todo-list`

**親機能**: `001-todo-dashboard`

**対象URL**: `/dashboard`

**作成日**: 2026-08-29

**ステータス**: Draft（後追い仕様化 — 既に実装済みの画面の挙動を記述したもの）

Todoの新規登録は、この画面から起動する別画面([Todo新規登録画面](../todo-new/spec.md))で
行う。本書はTodo一覧の閲覧と削除のみを対象とする。

## ユーザーシナリオ・受け入れテスト *(必須)*

### ユーザーストーリー1 - Todo一覧の閲覧 (優先度: P1)

訪問者がこの画面を開くと、現在存在する全てのTodoが、名前・期限・担当者・ステータスとともに
表示される。

**この優先度の理由**: 一覧が見えなければ何も操作できない。この画面の最小構成(MVP)。

**独立テスト方法**: 事前準備なしにこの画面を開く。Todoが既にあれば4項目とともに一覧表示さ
れる。1件も無ければ、空である旨のメッセージが表示される。

**受け入れシナリオ**:

1. **前提** Todoが1件以上存在する、**操作** 訪問者がこの画面を開く、**結果** 各Todoの名前・
   期限・担当者・ステータスが、追加された順(古い順)に表示される — FR-003参照。
2. **前提** Todoが1件も存在しない、**操作** 訪問者がこの画面を開く、**結果**
   「Todoがありません」というテキストが、空のテーブルの代わりに表示される。

---

### ユーザーストーリー2 - Todoの削除 (優先度: P2)

訪問者が不要になったTodoを、確認操作を経て削除する。

**この優先度の理由**: 一覧を整理する上で有用だが、閲覧だけでもこの画面は成立するため、閲覧
の次の優先度とする。

**独立テスト方法**: 一覧に1件以上Todoがある状態で削除操作を行い、確認後に一覧から消える
ことを確認する。

**受け入れシナリオ**:

1. **前提** 一覧にTodoが存在する、**操作** 訪問者がその行の「削除」ボタンをクリックする、
   **結果** 「このTodoを削除しますか？」という文言の確認ダイアログが表示される。
2. **前提** 確認ダイアログが表示されている、**操作** 訪問者が確認する(OK)、**結果** その
   Todoが一覧から即座に削除される。
3. **前提** 確認ダイアログが表示されている、**操作** 訪問者がキャンセルする、**結果** Todo
   は変更されず一覧に残る。
4. **前提** 訪問者が確認操作を行った後、**操作** 削除リクエストがサーバーエラーまたは
   ネットワークエラーで失敗する、**結果** Todoは一覧に残り、訪問者にはエラーメッセージは
   表示されない(削除操作は何も起きなかったように見える)。

### エッジケース

- Todoが0件のとき: テーブル全幅にわたって「Todoがありません」が表示される(ユーザースト
  ーリー1)。
- 削除確認のキャンセル: 変更なし(ユーザーストーリー2 シナリオ3)。
- 削除リクエストの失敗: ユーザーストーリー2 シナリオ4を参照。
- 過去の操作で追加/削除したTodoが、別のタイミングで見えなくなっている場合がある — 現在の
  データ基盤の既知の制約であり([機能概要](../../spec.md)の前提事項を参照)、この画面の仕様
  の範囲外。

## 要件 *(必須)*

### 機能要件 — 一覧表示

- **FR-001**: 画面は以下の列をこの順番で持つテーブルを表示しなければならない: `Todo名`、
  `期限`、`担当者`、`ステータス`、および各行の削除操作を含む見出しなしの操作列。
- **FR-002**: 各行は1件のTodoについて、その名前・期限・担当者・ステータスバッジ(ステータ
  ス文字列)を表示しなければならない。
- **FR-003**: Todoは追加された順(古い順)で一覧表示されなければならない。それ以外の並び順
  (期限順・ステータス順など)は提供しない。
- **FR-004**: Todoが0件のとき、画面はテーブル行の代わりに「Todoがありません」というテキス
  トを表示しなければならない。
- **FR-005**: 画面は一覧に対するソート・絞り込み・検索の機能を提供してはならない。
- **FR-006**: 画面は既存Todoの編集機能を提供してはならない — 一覧からできる操作は削除のみ
  で、新規登録は[Todo新規登録画面](../todo-new/spec.md)が担う。

### 機能要件 — Todoの削除

- **FR-007**: 各行は「削除」というラベルのボタンを持ち、これをクリックするとそのTodoの削除
  処理が始まらなければならない。
- **FR-008**: 「削除」をクリックすると、実際の削除処理が行われる前に「このTodoを削除します
  か？」という正確な文言の確認ダイアログを表示しなければならない。
- **FR-009**: 訪問者が確認した場合、画面は該当Todoを即座に一覧から削除しなければならない。
  訪問者がダイアログをキャンセルした場合、Todoは変更されずに残らなければならない。
- **FR-010**: 確認後の削除リクエストが失敗した場合、画面はそのTodoを一覧に残さなければなら
  ない。この場合、訪問者にエラーメッセージは表示されない。

### 主要エンティティ

Todoエンティティの定義は[機能概要](../../spec.md)を参照。

## 成功基準 *(必須)*

### 測定可能な成果

- **SC-001**: 訪問者は、この画面の読み込みが完了した時点で、定義された並び順(FR-003)の
  Todo一覧全体を、追加の読み込みステップなしに確認できる。
- **SC-002**: 訪問者はTodoを削除でき、FR-008の正確な確認文言を経て、10秒以内に一覧から削除
  されたことを確認できる。
- **SC-003**: 削除ボタンの単純なクリックだけでは、FR-008の確認ダイアログを経ずに削除が実行
  されることは0%である。

## 前提事項

- 削除は確認後に即座かつ恒久的に行われ、取り消し(undo)や復元の手段は無い。
- その他の前提事項は[機能概要](../../spec.md)を参照。
