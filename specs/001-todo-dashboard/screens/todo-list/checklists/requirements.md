# 仕様品質チェックリスト: Todo一覧

**目的**: 設計(`/speckit-plan`)に進む前に、仕様の完全性と品質を検証する
**作成日**: 2026-08-29
**対象**: [ユースケース記述1](../../../../doc/フロントエンド設計書/業務1_Todoダッシュボード/ユースケース記述1_Todo一覧.md)・[画面定義書1](../../../../doc/フロントエンド設計書/業務1_Todoダッシュボード/画面定義書1_Todo一覧.md)

## 内容の品質

- [x] 実装詳細(言語・フレームワーク・API仕様等)が含まれていない
- [x] タイトルが業務行為の名前になっている(「〜画面」という画面名になっていない)
- [x] 目次があり、体系的に読める構成になっている
- [x] ユーザーストーリー形式(優先度・独立テスト可否等)を使っていない —
  ユースケース記述(アクター・事前条件・基本フロー・代替/例外フロー・事後条件)のみ
- [x] エンティティ/データモデルの定義を含んでいない(サーバーサイドの関心事)

## ユースケース定義の品質

- [x] [要確認]マーカーが残っていない
- [x] 各ユースケースに基本フロー・代替/例外フローが定義されている
- [x] スコープの境界が明確である(新規登録は別画面が担当することを明記)

## 画面定義の品質

- [x] 画面入出力仕様に、画面上の全要素(入力・出力・ボタン)が列挙されている
- [x] 入出力区分(入力/表示/操作)と種別(具体的なUI部品)が別の列になっており、種別欄に区分を括弧書きで詰め込んでいない
- [x] 項目単位の見た目・制約が、各項目の行の中に記載されており、表外の補足コメントが
  ない
- [x] 入力項目について、プレースホルダの有無が明記されている(この画面には入力項目が
  無いため該当なし)
- [x] 処理仕様の1行目が初期表示になっている
- [x] 処理仕様の行順が、画面上の操作対象の並び順とおおむね一致している
- [x] 処理仕様がフロントエンドの範囲に閉じている(API/DBの内部仕様に踏み込んでいない)
- [x] 全ての画面入出力仕様の項目が、いずれかの処理仕様の行から参照されているか、
  それ自体が出力専用の表示項目として説明が完結している

## 備考

- 未完了の項目がある場合は、`/speckit-clarify`または`/speckit-plan`に進む前にユースケース
  記述・画面定義書を修正すること
