# ADR-0018: E2E仕様書のテストケース導出にブラックボックステスト技法を明示する

## ステータス

Accepted (2026-08-31)

## コンテキスト

ユーザーから、`update-e2e-test-spec`スキルが導出するE2E観点のテストケースが一般的な
ソフトウェアテストのテストケース分析手法(同値分割・境界値分析・デシジョンテーブル
テスト・状態遷移テスト・ユースケーステストなど)に沿っているか、また具体的な技法名が
ルールに明示されているか、という指摘があった。

調査の結果、既存の3区分(a. ユースケースに基づくケース/b. 画面入出力仕様に基づくケース/
c. 処理仕様に基づくケース)は、実質的には以下の技法をなぞっていた:

- a → ユースケーステスト
- b(必須項目・固定選択肢) → 同値分割
- b(文字数上限) → 境界値分析(ただし上限のみ。下限や「上限−1」は対象外)
- c(分岐) → 条件網羅・分岐網羅

しかし、技法名としてルール(`.claude/skills/update-e2e-test-spec/SKILL.md`・
constitution.md)に明示されていたのは「境界値」の1箇所のみで、しかも上限文字数にしか
適用されていなかった。「同値分割」「デシジョンテーブルテスト」「状態遷移テスト」という
用語自体はどこにも書かれておらず、以下の実害があった:

- 境界値分析が上限のみで、下限(最小文字数)が定められている項目があっても境界値ケースが
  作られない。
- 処理仕様の1行が複数の独立した条件の組み合わせで結果が決まる場合でも、単純な
  「成功/失敗」の2分岐としてしか扱われず、条件の組み合わせ(デシジョンテーブル)を
  網羅する手立てが無かった。
- 状態遷移テストが独立した技法として存在せず、`TodoNewModal.tsx`の保存中/保存失敗の
  ような複数状態を持つ要素のテストケースは、たまたま画面入出力仕様の行として拾えている
  だけで、状態と遷移を体系的に洗い出す仕組みが無かった。

技法名が明示されていないと、どの技法を使ってどこまで網羅したかを後から監査できず、
「実質的に技法をなぞってはいるが、その技法が本来要求する境界・組み合わせを網羅しきれて
いない」というギャップが見えにくくなる。

## 決定

`update-e2e-test-spec`のテストケース導出区分を3種類から4種類に拡張し、それぞれに
使用する技法名を明示する:

1. **ユースケーステストによるケース**(技法: ユースケーステスト) — 従来通り。
2. **同値分割・境界値分析によるケース**(技法: 同値分割・境界値分析) — 必須項目・
   固定選択肢の同値分割は従来通り。境界値分析は上限だけでなく、下限(最小文字数)が
   別途明記されている場合も「下限文字数(有効境界)」「下限文字数-1(無効境界)」の
   2ケースを追加する。なお、固定の見出し・一覧テーブルの列のデータ表示・行ごとの操作が
   対応する行にのみ作用することなど、上記いずれの技法にも当てはまらない画面入出力仕様の
   行は、「技法に基づかない基本表示確認」として明示的に区別した上でこの区分に含める
   (Principle VIが画面上の全要素を1行ずつ列挙することを要求しているため、その行の内容を
   機械的にケース化する義務は技法の有無によらず残る)。
3. **条件/分岐テストによるケース**(技法: 条件網羅・分岐網羅、デシジョンテーブルテスト) —
   単一条件の分岐は従来通り。複数の独立条件の組み合わせで結果が決まる行は、
   デシジョンテーブルとして条件の組み合わせを書き出し、組み合わせごとに1ケース作る。
4. **状態遷移テストによるケース**(技法: 状態遷移テスト、新規区分) — 同じ要素が複数の
   表示状態を取り得る場合、状態と遷移を洗い出し、各状態への遷移が最低1回発生する
   ケースと、許可されない遷移操作(二重送信等)で状態が変わらないことを確認するケースを
   作る。該当が無い画面でも見出し自体は残し、技法として検討した上で該当なしだったことを
   後から読み取れるようにする。

constitution.mdのDevelopment Workflow(Spec-Driven)にも、この5技法(条件/分岐テストと
デシジョンテーブルテストは1項目としてまとめて数える)をMUST要件として明示し、
「どの技法から導出したケースか」を監査可能にした。

組み合わせテスト・探索的テストなど、この5技法でカバーしない人の判断によるテスト観点は
従来通り「追加のテスト観点」に留める(機械的導出の対象にしない)。

## 影響

- `.claude/skills/update-e2e-test-spec/SKILL.md`の導出ルール・出力ファイル構成
  (3見出し→4見出し)を書き換えた。
- constitution.mdのDevelopment Workflow(Spec-Driven)に技法名を明記(v2.13.0、MINOR)。
- 既存の2つのE2E仕様書(`E2E仕様書_Todo一覧.md`・`E2E仕様書_Todo新規登録.md`)を
  `update-e2e-test-spec`スキルで再生成し、新区分・拡張された境界値分析・状態遷移テストの
  区分を反映する(この決定に続くコミットで実施)。
