# ADR-0014: tasks.md・checklistsを`specs/`から`tracking/`へ移動する

## ステータス

Accepted (2026-08-31)

## コンテキスト

ADR-0013で`specs/**` + `docs/**`の分散を`doc/`ツリーへ統合した際、`tasks.md`と
`screens/*/checklists/requirements.md`だけは「GitHub Issue追跡用のタスク一覧・
仕様品質チェックという*プロセス/追跡用の成果物*であり、業務が読む設計書ではない」
という理由で、あえて`specs/001-todo-dashboard/`にそのまま残した。

しかし、`doc/`側の全ファイルが移動・改名された結果、`specs/`ディレクトリには
「設計書ではない2種類のファイルだけ」が残る形になった。ユーザーから「specディレクトリに
残ったものが仕様書じゃなくて違和感がある」という指摘があった — `specs/`という
ディレクトリ名自体が「仕様(spec)」を連想させるため、仕様書ではないものだけが
残っている現状は名前と中身が矛盾しており、紛らわしい。

## 決定

`tasks.md`と`screens/*/checklists/requirements.md`を、新設する`tracking/<業務>/`
(業務ごとのディレクトリ名は`doc/フロントエンド設計書/`と揃える。例:
`tracking/業務1_Todoダッシュボード/`)に移動する。`specs/`ディレクトリは空になるため
削除する。

- `tracking/`は英語の中立的な名前とする。GitHub Issue番号・タスクID(T001等)は
  英語圏の仕組みであり、内容自体が英語混じりのため、無理に日本語ディレクトリ名にしない
  (`doc/`配下の設計書は業務内容そのものなので日本語名にする、という使い分け)。
- 各ファイルの`doc/`への相対リンクは、移動後もディレクトリの深さが変わらないため
  文字列としては同じ`../`の数で書けるはずだったが、実際に`ls`で検証したところ
  `screens/*/checklists/requirements.md`側の相対リンクが**移動前から**深さを1つ
  誤っていたバグ(`../../../../doc/...`と書かれていたが、正しくは
  `../../../../../doc/...`)を発見した。今回の移動と同時に修正した。

## 検討した選択肢

- **`specs/`にそのまま残す(ADR-0013の決定を維持)**: 却下。ユーザーからの明確な
  違和感の指摘があり、`specs/`という名前と中身(非設計書)の不一致を解消する方が
  分かりやすい。
- **`.specify/tracking/`のようにspec-kit内部状態として隠す**: 却下。GitHub Issue
  対応表はレビュー時に人間が頻繁に参照するものであり、隠しディレクトリに置くと
  発見しづらくなる。

## 影響

- `specs/`ディレクトリはリポジトリから削除される。
- `tracking/業務1_Todoダッシュボード/`が`tasks.md`・`screens/*/checklists/`の新しい
  置き場所になる。
- 各ファイル内の相対リンクを新しい深さに合わせて更新した(上記のバグ修正含む)。
