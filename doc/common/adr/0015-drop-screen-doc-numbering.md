# ADR-0015: ユースケース記述/画面定義書/E2E仕様書のファイル名から連番を外す

## ステータス

Accepted (2026-08-31)

## コンテキスト

ADR-0013で`doc/フロントエンド設計書/<業務>/`配下の画面ごとのドキュメントを
`ユースケース記述<N>_<画面名>.md`・`画面定義書<N>_<画面名>.md`・`E2E仕様書<N>_<画面名>.md`
という、連番+画面名の組み合わせで命名した。これはユーザーが最初に提示した構成例
(「ユースケース記述１」「ユースケース記述２」)をそのまま踏襲したものだった。

ユーザーから、その連番は「複数ファイルがあり得る」ことを示す説明用の仮の番号であり、
実際の画面名(Todo一覧・Todo新規登録)に置き換えた後は番号自体を残すつもりはなかった、
という指摘があった。画面名のsuffixで既に一意に識別できるため、連番は冗長かつ、番号の
意味(登場順?優先順?)が実は何も無いのに意味ありげに見えてしまう。

## 決定

`ユースケース記述<N>_<画面名>.md`のような連番付き命名を廃止し、`ユースケース記述_<画面名>.md`
(画面名のみで一意に識別する)に変更する。対象:

- `ユースケース記述_Todo一覧.md`(旧: `ユースケース記述1_Todo一覧.md`)
- `ユースケース記述_Todo新規登録.md`(旧: `ユースケース記述2_Todo新規登録.md`)
- `画面定義書_Todo一覧.md`(旧: `画面定義書1_Todo一覧.md`)
- `画面定義書_Todo新規登録.md`(旧: `画面定義書2_Todo新規登録.md`)
- `E2E仕様書_Todo一覧.md`(旧: `E2E仕様書1_Todo一覧.md`)
- `E2E仕様書_Todo新規登録.md`(旧: `E2E仕様書2_Todo新規登録.md`)

`詳細設計書.md`・`画面遷移図.md`は元々1業務に1ファイルなので対象外(変更なし)。

あわせて、番号無しでは画面を識別できなくなる箇所(例: 本文中の`[ユースケース記述1]`
のような裸のリンクテキスト)は、`[ユースケース記述(Todo一覧)]`のように画面名を括弧書きで
補って一意性を保った。

`update-e2e-test-spec`・`update-screen-flow-diagram`の各Skillと`check-spec-sync.sh`の
ファイル名パターン(`<N>_<画面名>.md`)も`_<画面名>.md`に修正した。

## 影響

- 6ファイルをリネームし、リポジトリ内の全ての相互参照リンクを更新した。
- `check-spec-sync.sh`のファイル名対応ロジックを、番号(`screen_num`)ベースの突き合わせ
  から画面名(`screen_name`)ベースの突き合わせに変更した(単純化: 対応する
  `E2E仕様書_<画面名>.md`をファイル名の完全一致で探すだけになった)。
- ADR-0013本文中の`<N>_<画面名>.md`という表記は、当時の決定を記録した歴史的記述として
  そのまま残す(constitution.mdのSync Impact Reportの過去エントリを書き換えない、という
  このプロジェクトの既存の方針に合わせている)。
