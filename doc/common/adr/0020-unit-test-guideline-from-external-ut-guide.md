# ADR-0020: 外部UTガイドラインから抽出したユニットテスト作成ガイドラインの導入

## ステータス

Accepted (2026-08-31)

## コンテキスト

ユーザーが、担当する別システム(Java/PHP、API・SharedService・Admin・Batchという
アーキテクチャ)向けのM/UT(モジュールテスト/ユニットテスト)ガイドラインを共有し、
このプロジェクトへの示唆を求めた。指摘した点:

- C2(分岐)カバレッジ100%必須+証跡必須という運用は、このプロジェクトの
  coverageThreshold(Principle IX, 95%)より厳格で、判断の余地を残さない設計として
  優れている。
- 同値分割による分岐網羅・2点境界値分析・バリデーション仕様と試験ケースの対応表・
  エラー推測のカタログ(NULL・DB関連・日付境界・特殊文字列等)は、言語やフレームワークに
  依存しない一般的な技法であり、このプロジェクトにもそのまま転用できる。
- 一方で、条件が独立していない場合のデシジョンテーブル技法への明示的な言及が無いこと、
  状態遷移テストが技法として独立していないことは、まさにこのプロジェクトがE2Eテスト
  設計で既に発見・修正した抜け穴(ADR-0018)と同じ種類のギャップだった。

その後ユーザーから、このガイドラインから良いエッセンスだけを抽出し、このプロジェクトの
「ユニットテスト作成時の留意点」に加えてほしいという指示があった。

## 決定

`doc/common/ユニットテスト作成ガイドライン.md`を新設し、以下を移植・翻案する:

- **テスト範囲**: このプロジェクトの実際のファイル種別(Reactコンポーネント・
  Route Handler・`src/lib/**`)ごとに、外部ガイドラインの「Publicメソッド単位」という
  考え方を翻案する。
- **分岐網羅のための同値分割**: 複合条件の各オペランドを独立して真偽網羅する手順を、
  このプロジェクトの実例(`src/app/api/todos/route.ts`のバリデーション)で示す。
- **デシジョンテーブル**(外部ガイドラインに無かったものを追加): 条件が独立していない
  場合の組み合わせ網羅。
- **入力チェック→試験ケースの対応表**: Bean Validationの注釈カタログの代わりに、この
  プロジェクトの素のif文チェックパターン(必須・文字数上限/下限・enum・正規表現)に
  対応する表を新規に作成する。
- **境界値分析(2点)**。
- **エラー推測**: NULL/undefined・空文字空白ゼロ・日付境界・特殊文字列に加えて、
  「二重送信・同一操作の連続実行」(`TodoNewModal.test.tsx`の再送信ケースが実例)を
  追加する。外部ガイドラインのカタログにはこの観点が無かった。
- **状態遷移テスト**(外部ガイドラインに無かったものを追加、ADR-0018のE2E版と対の
  ユニットテスト版として位置づける)。
- **アサーションの原則**: 期待値は実装ではなく設計書から設定する、という外部ガイドラインの
  重要な注意書きをそのまま踏襲する。
- **トレーサビリティ**: 各テストケースの説明文からどの技法由来か読み取れるようにする
  (技法名の機械的な明記は求めない)。

constitution.mdにCore Principle X(Unit Test Case Design Technique)として追加し
(v2.15.0, MINOR)、この資料への準拠をMUST要件とする。

## 対象外・スコープ外とした点

- 外部ガイドラインのAPIレスポンス/DB/Redis/ログ/SQL結合・集約に関する詳細な観点は、
  このプロジェクトに該当する概念が無い(DBもRedisも使わないモックバックエンド構成)ため
  移植しない。
- Admin(PHP画面打鍵)特有の観点(ページネーション・ソート・折り畳みメニュー等の画面部品
  チェックリスト)は、このプロジェクトのE2E仕様書導出(update-e2e-test-specスキル・
  ADR-0018)側の関心事であり、ユニットテストガイドラインには含めない。
- 既存のテストファイル(54件)に対して、技法名を遡って書き込む改修は行わない
  (新規ルールは今後のテスト作成に適用する。歴史的な成果物を書き換えないという
  プロジェクトの既存方針に合わせている)。

## 影響

- `doc/common/ユニットテスト作成ガイドライン.md`を新規作成。
- constitution.mdにCore Principle Xを追加(v2.15.0)。
- 既存テストの書き換えは発生しない。
